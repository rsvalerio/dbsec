## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TransformKind, ColumnConfig, TableConfig, ProtectedColumn and columns::build live in crates/proxy. They carry the schema.table.column key-naming convention that names the deterministic key AND is bound into every envelope AAD, plus the rule that strict_row_binding is a property of the table rather than the column.

A library user who assembles transforms by hand has to rediscover that convention from the source. Naming a key wrong loses cross-column relocation protection silently — no error is ever raised, at write time or read time.

Move the policy types and the builder into dbsec-core as a backend-neutral model (no serde-from-TOML assumptions in the types themselves). The proxy keeps its TOML Config and its startup validation, deserializing into the core model rather than owning it. Config validation that is policy-level rather than TOML-level — a row_key on a table with no encrypt column, an FPE domain under MIN_FPE_DIGITS — should move with the model so a library caller gets the same refusals.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Add a `toml` feature that parses the proxy's [[column]]/[[table]] tables into the core policy model, so a team running both library and proxy reads one policy file rather than two sources that can drift. The types stay serde-free by default; the feature adds the derive.

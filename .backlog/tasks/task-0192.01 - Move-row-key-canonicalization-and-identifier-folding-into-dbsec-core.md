## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
crates/proxy/src/rowkey.rs (canonical(), Format, supported(), the oid table) and the PostgreSQL identifier folding used to build CellContext strings are pure functions with no proxy dependency, yet a library user binding rows or naming columns must reproduce both byte-exactly.

Why it fails silently: 0007, +7 and 7 must canonicalize to the same RowKey, as must upper-case, braced and unhyphenated uuids. Folding is ASCII-only downcase plus a 63-byte clip (NAMEDATALEN - 1) — Rust to_lowercase would fold characters the server leaves alone. Diverge on either and library-written values simply never open through the proxy, with no error at write time.

Move both into dbsec-core (rowkey as a public module, folding next to CellContext) and have the proxy call them. One implementation, so the two sides of a name or key comparison cannot drift.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Moved crates/proxy/src/rowkey.rs to crates/core/src/rowkey.rs and lifted fold_identifier/MAX_IDENTIFIER_BYTES/truncate_identifier out of crates/proxy/src/config.rs into a new crates/core/src/ident.rs, with their tests. Error::RowKeyType moved from the proxy Error to dbsec_core::Error, so canonicalisation reports the same failure to a library caller as to the proxy; proxy call sites reach it through the existing Error::Wire(#[from] dbsec_core::Error). No behaviour change: the 13 moved tests pass unchanged, and both functions are byte-identical to what the proxy ran.

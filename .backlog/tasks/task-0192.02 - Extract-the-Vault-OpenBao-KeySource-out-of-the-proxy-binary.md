## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
VaultKeySource lives in crates/proxy/src/vault.rs (~1,300 LOC), so the library ships only FileKeySource — whose own doc comment says dev/test. The README advertises Vault/OpenBao-backed keys as a headline feature; it is not a library feature today.

What has to travel: Transit-wrapped DEK minting and unwrap-on-demand, the KV v2 index-key store with cas = 0 minting and versioned records, the legacy shared-map migration, the DEK/index caches and the token-lease watchdog.

Shape: a separate dbsec-vault crate is preferred over a feature on dbsec-core, so that vaultrs, url and a TLS stack stay out of the dependency graph of an application that only wants FileKeySource or its own KeySource impl. Either way the constraint is that dbsec-core keeps no dependency on any one key backend — Error::KeyBackend already boxes the cause for exactly this reason.

The token watchdog is the one piece that needs an async runtime; keep it optional so a synchronous embedder is not forced to take tokio.

## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
crates/core/src/pgwire.rs (~540 LOC) is the PostgreSQL wire codec — startup packets, message framing, DataRow/Bind encoding. Only the proxy uses it, yet it sits in the crate an embedded application links. sync.rs (the Unpoisoned trait) is in the same position.

An application doing code-time field encryption never speaks the wire protocol; it hands values to sqlx or tokio-postgres. Carrying the codec makes dbsec-core look like a proxy library rather than a crypto library, and it is the part most likely to keep changing.

Move pgwire to its own crate (or into crates/proxy) and leave dbsec-core protocol-free. Check whether the pgwire-specific Error variants — BadMessageLength, StartupMessageTooLarge, WireFieldOverflow, MalformedBackend — should travel with it; Error is #[non_exhaustive], so removing variants is still a breaking change to match. Keep the fuzz/pgwire target building wherever the code lands.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Moved crates/core/src/pgwire.rs into a new dbsec-pgwire crate, with the four wire-only Error variants (BadMessageLength, StartupMessageTooLarge, WireFieldOverflow, MalformedBackend) as that crate own Error enum. Decision on the AC: the variants move. Nothing outside the codec ever constructed or matched them, so keeping them in dbsec_core::Error would have left a caller that never speaks the protocol matching on frame errors it cannot receive. The proxy gained Error::Pgwire(#[from] dbsec_pgwire::Error) alongside Error::Wire. The wire property tests moved from crates/core/tests/props.rs to crates/pgwire/tests/props.rs; the fuzz/pgwire target builds and now depends on dbsec-pgwire. dbsec-core is now protocol-free and I/O-free.
<!-- SECTION:NOTES:END -->

## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The last mile of easy to reuse: what a Rust developer meets in the first five minutes.

- Feature-gate the optional surface so the default build is minimal. serde and toml are in dbsec-core only for FileKeySource keyfile parsing; an application with its own KeySource should not compile a TOML parser. Propose: default = [], keyfile = ["serde", "toml"], fpe, tokens as needed. Keep zeroize, aes-gcm, hmac unconditional.
- Crate metadata for crates.io: keywords, categories, readme, documentation, a rust-version MSRV, and a decision on whether dbsec-core publishes ahead of the proxy.
- Crate-level rustdoc that is an actual tutorial, not a module list: the threat model in three sentences, the envelope versions, a runnable seal/open/search example, and an explicit statement of what the library does NOT protect (equality and frequency leakage from deterministic transforms, masking only where the library is called).
- Deny missing_docs on the public API, or state why not. The workspace deliberately leaves it out today.
- A README section for the library path, distinct from operating the proxy.
- Decide the semver contract: Error is #[non_exhaustive], but the envelope format and the AAD layout are the real compatibility surface and deserve to be stated as such.

## Implementation Notes

dbsec-derive must publish before dbsec-core (core depends on it optionally). The derive feature pulls syn/quote/proc-macro2 — already in the graph via serde_derive, so the default build cost is unchanged.

Landed on lib/publishable. AC#2: `cargo publish --dry-run` passes for dbsec-derive; for dbsec-core it stops at "no matching package dbsec-derive" until the derive is on crates.io (cargo resolves deps from the registry even on dry-run). Publish order: dbsec-derive, then dbsec-core. Left unconditional: fpe/hmac/aes (small, and the format table promises them). rust-version 1.85 verified locally with rustup 1.85 and `--locked`; proxy excluded (Duration::from_mins is 1.91, icu deps need 1.86).
